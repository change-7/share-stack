# Share Stack

안드로이드의 여러 앱에서 공유한 텍스트, 이미지, 동영상, PDF와 일반 파일을 하나의 스택에 모아두었다가 필요한 항목을 선택해 다시 공유하는 앱입니다.

예를 들어 A 앱에서 사진을, B 앱에서 파일과 텍스트를 Share Stack으로 보내면 항목들이 앱 안에 누적됩니다. 이후 여러 항목을 선택해 다른 앱으로 한 번에 공유할 수 있습니다.

## 주요 기능

- 텍스트, 이미지, 동영상, PDF, 일반 파일 수집
- 여러 앱에서 받은 항목을 하나의 스택으로 누적
- 동일한 내용의 중복 항목 자동 제외
- 이미지·동영상·PDF 썸네일 미리보기
- 설정에서 썸네일형 또는 목록형 보기 방식 선택
- 선택 공유, 텍스트 복사, 선택 삭제
- 선택한 스택 항목을 지정한 폴더에 보관 (텍스트는 TXT 파일)
- 선택한 이미지 여러 장을 하나의 클립보드에 복사
- 상단 카메라 버튼에서 앱 내 카메라로 사진·동영상을 촬영해 즉시 스택에 추가
- 길게 눌러 항목 순서 변경, 전체 선택·해제
- 설정에서 1일·7일·30일 자동 만료 선택
- 빠른 설정창에서 카메라 추가·클립보드 텍스트 추가·전체 공유 실행
- 앱 아이콘과 알림에 현재 스택 개수 표시
- 공유받은 뒤 앱을 자동으로 열지 않고 백그라운드에서 수집
- 필요하면 설정에서 공유받은 뒤 앱 열기 활성화
- 브라우저 이미지 공유 시 URL 텍스트를 함께 저장할지 설정
- 공유 후 스택 자동 비우기 설정
- 항목별 잠금 보관: 자동 비우기 뒤에도 중요한 항목 유지
- Tailscale을 통한 Mac 메뉴 앱과 양방향 파일·텍스트 전송

## 사용 방법

1. 다른 앱에서 텍스트, 사진 또는 파일의 **공유** 메뉴를 엽니다.
2. 공유 대상에서 **Share Stack**을 선택합니다.
3. 다른 앱에서도 같은 방법으로 항목을 계속 추가합니다.
4. Share Stack을 열고 보낼 항목을 선택합니다.
5. **선택공유**를 누르고 대상 앱을 선택합니다.

## 파일과 텍스트 공유 방식

수신 앱과의 호환성을 높이기 위해 파일과 텍스트를 분리해서 처리합니다.

- 사진과 파일은 안드로이드 공유 화면으로 전달합니다.
- 선택된 텍스트는 클립보드에 자동으로 복사합니다.
- 대상 앱이 열리면 입력창에 텍스트를 붙여넣으면 됩니다.
- 텍스트만 선택한 경우 공유 화면을 열지 않고 클립보드에 바로 복사합니다.

파일이 여러 개일 때는 다음 방식 중 하나를 선택할 수 있습니다.

- **한번에 공유**: 여러 파일을 원래 형식 그대로 전달합니다.
- **ZIP으로 공유**: 여러 파일을 하나의 ZIP 파일로 묶어 전달합니다.

대상 앱이 다중 첨부를 제대로 지원하지 않는다면 ZIP 공유를 사용하세요.

## 보기 및 설정

- 설정의 **보기 방식**에서 썸네일형과 목록형을 선택할 수 있습니다.
- 설정에서 보관 폴더를 지정한 뒤, 스택에서 항목을 선택하고 **보관**을 누르면 파일을 폴더로 복사합니다. Android 문서 선택기에 표시되고 쓰기를 지원하는 네트워크 폴더도 사용할 수 있습니다.
- **공유받은 뒤 앱 열기**를 끄면 다른 앱에서 공유해도 Share Stack 화면이 나타나지 않고 항목만 쌓입니다.
- **공유 후 스택 비우기**를 켜면 공유 시트에서 대상 앱을 선택한 뒤 해당 스택을 비웁니다. 공유 시트를 취소하면 스택은 유지됩니다.
- 항목 미리보기에서 **잠금 보관**을 선택하면 공유 후 자동 비우기를 켜도 그 항목은 남습니다. 잠금 항목도 직접 선택 삭제할 수 있습니다.
- **알림을 누르면 전체 공유**를 켜면 알림 본문을 눌러 현재 스택 전체의 공유 화면을 바로 열 수 있습니다.
- **스택 알림 고정**을 켜면 스택이 있는 동안 알림을 지울 수 없게 하여, 알림 배지를 지원하는 런처에서는 앱 아이콘의 개수도 유지합니다.
- Android 13 이상에서는 알림과 앱 아이콘의 개수 표시를 위해 알림 권한이 필요합니다.

## 설치

지원 버전은 **Android 8.0(API 26) 이상**입니다.

- [최신 디버그 APK](./share-stack-debug.apk)

APK를 휴대전화로 내려받아 실행하세요. 브라우저나 파일 관리자에서 설치할 때 기기 설정에 따라 **출처를 알 수 없는 앱 설치 허용**이 필요할 수 있습니다.

현재 제공되는 APK는 개발 및 테스트용 디버그 빌드입니다.

## Mac 앱

Mac 메뉴 앱은 `./script/build_and_run.sh`로 빌드하고 실행합니다. 기존 실행을 종료한 뒤 최신 앱을 작업 폴더 최상단의 `ShareStackMac.app`에 반영합니다. Xcode에서는 `macos/ShareStackMac/ShareStackMac.xcodeproj`의 `ShareStackMac` scheme을 사용할 수 있습니다.

1. Mac과 Galaxy를 같은 Wi-Fi에 연결하거나 두 기기에서 Tailscale을 켭니다.
2. Mac의 Share Stack 메뉴에서 **QR** 탭을 열고 **Wi-Fi** 또는 **Tailscale**을 선택한 뒤 QR을 스캔합니다. Tailscale은 두 기기를 같은 Tailscale 네트워크에 연결하면 서로 다른 Wi-Fi나 모바일 데이터에서도 사용할 수 있습니다. Tailscale 주소가 표시되지 않으면 Mac에서 Tailscale을 연결하고 **새로고침**을 누릅니다. Galaxy의 **Mac 연결** 화면에서 **같은 Wi-Fi에서 Mac 검색**으로도 로컬 주소를 찾을 수 있습니다. 최초 연결에는 QR의 짝 토큰과 TLS 인증서 지문이 필요합니다. 수동 입력 값은 **연결 정보** 탭에서 연결 경로를 선택해 복사합니다.
3. Galaxy Share Stack 상단 컴퓨터 버튼에서 **선택 보내기** 또는 **받기**를 누릅니다.

전송 서버는 포트 `8765`에서 Bonjour 서비스 `_sharestack._tcp`를 광고하고, 루프백·로컬 사설 IPv4·Tailscale IPv4 연결을 받습니다. TLS 인증서 지문과 짝 토큰을 함께 확인합니다. 파일은 4 MiB 조각으로 전송하며 최대 크기는 20 GiB입니다. Mac 업로드 조각과 Galaxy 다운로드 조각은 디스크에 저장되므로 앱이나 연결이 중단돼도 다시 연결하면 마지막 위치부터 계속됩니다. 최종 파일은 SHA-256을 검증한 뒤 보관함에 기록합니다.

메뉴 앱에서 파일을 선택하거나 클립보드 텍스트를 직접 추가하면 Galaxy 전송 대기열에 들어갑니다.

### Mac 수신 방식과 보관함

메뉴 상단의 **설정**에서 수신 방식과 저장 폴더를 선택합니다. 기본 저장 폴더는 `~/Downloads/Share Stack`이며 기본 수신 방식은 **보관함에서 확인 후 저장**입니다.

메뉴바 아이콘을 누르면 항상 **보관함** 탭이 먼저 열립니다. 수신 대기 파일이 있으면 메뉴바 아이콘 옆에 개수 배지가 표시되며, 수신하거나 취소하면 갱신됩니다. 대기 파일이 없으면 배지가 사라집니다. 100개 이상은 `99+`로 표시하고 정확한 수는 아이콘 도움말과 보관함에서 확인합니다.

- **보관함에서 확인 후 저장**: 받은 파일을 앱 전용 임시 보관 폴더 `~/Library/Application Support/ShareStackMac/inbox-temporary`에 둡니다. 메뉴의 **보관함**에서 **수신**을 누르면 지정 폴더로 이동하고, **취소**를 누르면 임시 파일과 대기 항목을 삭제합니다. 앱을 재실행해도 선택하지 않은 파일은 유지됩니다. 기존 버전에서 받은 파일도 보관함에서 처리할 수 있습니다.
- **지정 폴더에 자동 저장**: 전송과 SHA-256 검증이 끝나면 지정 폴더에 바로 저장합니다. 저장 폴더 접근 실패 등으로 저장하지 못한 파일은 보관함에 남고 오류가 표시됩니다.

동일한 이름의 파일은 덮어쓰지 않고 번호를 붙입니다. 설정 변경은 이후 도착하는 파일부터 적용하며 이미 보관함에 있는 파일은 직접 수신하거나 취소합니다. 보관함에는 파일마다 **수신**·**취소** 버튼이 있고 **전체 수신**으로 현재 대기 중인 모든 파일을 저장할 수도 있습니다. 일부 파일이 실패해도 나머지를 계속 저장하며 실패한 파일은 보관함에 남습니다. 보관함은 한 화면에 세 건씩 표시하고 이전·다음 버튼으로 넘기므로 스크롤할 필요가 없습니다.

앱 데이터는 `~/Library/Application Support/ShareStackMac`에 저장하고, 짝 토큰과 TLS 파일 암호는 macOS Keychain에 보관합니다. 이전 인증서 형식은 원본 파일과 개인키를 보존하며 변환하고 인증서를 다시 발급하므로, 기존 연결이 있었다면 QR을 다시 스캔해야 합니다. 로컬 네트워크 검색은 Android의 NSD/Bonjour를 사용합니다. ([Android NSD API](https://developer.android.com/reference/android/net/nsd/NsdManager))

## API

외부 프로그램용 맥 API는 [API 사용 문서](docs/api.md)와 [OpenAPI 명세](docs/openapi.yaml)를 참고하세요. 보관함 조회·개별/전체 수신·취소·상태·기록·이벤트 조회와 휴대전화 송신 대기열 추가를 지원합니다.

## 안드로이드 제약

- 안드로이드 보안 정책 때문에 일반 앱이 모든 클립보드 복사를 백그라운드에서 계속 감시할 수는 없습니다. 텍스트를 스택에 추가하려면 다른 앱의 공유 메뉴에서 Share Stack을 선택해야 합니다.
- 여러 파일을 받을 수 있는지는 대상 앱의 구현에 따라 달라집니다. 일부 앱은 하나의 파일만 받거나 혼합 파일 형식을 거부할 수 있습니다.
- 이 경우 ZIP 공유를 사용하거나 텍스트를 별도로 붙여넣는 방식이 가장 안정적입니다.
