# Share Stack

안드로이드의 여러 앱에서 공유한 텍스트, 이미지, 동영상, PDF와 일반 파일을 하나의 스택에 모아두었다가 필요한 항목을 선택해 다시 공유하는 앱입니다.

예를 들어 A 앱에서 사진을, B 앱에서 파일과 텍스트를 Share Stack으로 보내면 항목들이 앱 안에 누적됩니다. 이후 여러 항목을 선택해 다른 앱으로 한 번에 공유할 수 있습니다.

## 주요 기능

- 텍스트, 이미지, 동영상, PDF, 일반 파일 수집
- 여러 앱에서 받은 항목을 하나의 스택으로 누적
- 동일한 내용의 중복 항목 자동 제외
- 이미지·동영상·PDF 썸네일 미리보기
- 설정에서 썸네일형 또는 목록형 보기 방식 선택
- 선택 공유, 선택 기기 전송, 선택 삭제
- 길게 눌러 항목 순서 변경, 전체 선택·해제
- 설정에서 1일·7일·30일 자동 만료 선택
- 빠른 설정창에서 클립보드 텍스트 추가·전체 공유 실행
- 앱 아이콘과 알림에 현재 스택 개수 표시
- 공유받은 뒤 앱을 자동으로 열지 않고 백그라운드에서 수집
- 필요하면 설정에서 공유받은 뒤 앱 열기 활성화
- 브라우저 이미지 공유 시 URL 텍스트를 함께 저장할지 설정
- 공유 후 스택 자동 비우기 설정
- 항목별 잠금 보관: 자동 비우기 뒤에도 중요한 항목 유지
- Tailscale을 통한 Mac 메뉴 앱과 양방향 파일·텍스트 전송

## 사용 방법

1. 다른 앱에서 텍스트, 사진 또는 파일의 **공유** 메뉴를 엽니다.
2. 공유 대상에서 **Share Stack**을 선택합니다.
3. 다른 앱에서도 같은 방법으로 항목을 계속 추가합니다.
4. Share Stack을 열고 보낼 항목을 선택합니다.
5. **선택공유**를 누르고 대상 앱을 선택합니다.

## 파일과 텍스트 공유 방식

선택한 파일과 텍스트를 안드로이드 공유 화면으로 전달합니다. 대상 앱에 따라 텍스트와 파일을 함께 받지 못할 수 있습니다.

파일이 여러 개일 때는 다음 방식 중 하나를 선택할 수 있습니다.

- **한번에 공유**: 여러 파일을 원래 형식 그대로 전달합니다.
- **ZIP으로 공유**: 여러 파일을 하나의 ZIP 파일로 묶어 전달합니다.

대상 앱이 다중 첨부를 제대로 지원하지 않는다면 ZIP 공유를 사용하세요.

## 보기 및 설정

- 설정의 **보기 방식**에서 썸네일형과 목록형을 선택할 수 있습니다.
- **공유받은 뒤 앱 열기**를 끄면 다른 앱에서 공유해도 Share Stack 화면이 나타나지 않고 항목만 쌓입니다.
- **공유 후 스택 비우기**를 켜면 공유 시트에서 대상 앱을 선택한 뒤 해당 스택을 비웁니다. 공유 시트를 취소하면 스택은 유지됩니다.
- 항목 미리보기에서 **잠금 보관**을 선택하면 공유 후 자동 비우기를 켜도 그 항목은 남습니다. 잠금 항목도 직접 선택 삭제할 수 있습니다.
- **알림을 누르면 전체 공유**를 켜면 알림 본문을 눌러 현재 스택 전체의 공유 화면을 바로 열 수 있습니다.
- **스택 알림 고정**을 켜면 스택이 있는 동안 알림을 지울 수 없게 하여, 알림 배지를 지원하는 런처에서는 앱 아이콘의 개수도 유지합니다.
- Android 13 이상에서는 알림과 앱 아이콘의 개수 표시를 위해 알림 권한이 필요합니다.

## 설치

지원 버전은 **Android 8.0(API 26) 이상**입니다.

- [최신 디버그 APK](./share-stack-debug.apk)

APK를 휴대전화로 내려받아 실행하세요. 브라우저나 파일 관리자에서 설치할 때 기기 설정에 따라 **출처를 알 수 없는 앱 설치 허용**이 필요할 수 있습니다.

현재 제공되는 APK는 개발 및 테스트용 디버그 빌드입니다.

`./gradlew assembleDebug`로 디버그 APK를, `./gradlew assembleRelease`로 R8 축소·리소스 축소가 적용된 릴리스 APK를 만듭니다. 릴리스 서명은 프로젝트 루트의 `keystore.properties`(`storeFile`, `storePassword`, `keyAlias`, `keyPassword`)가 있을 때 자동 적용되며, 이 파일과 키스토어는 git에서 제외됩니다. Android SDK 경로는 `ANDROID_HOME` 또는 `local.properties`로 지정합니다.

## Mac 앱

Mac 메뉴 앱은 `./script/build_and_run.sh`로 Release 빌드하고 실행합니다. 기존 실행을 종료한 뒤 최신 앱을 작업 폴더 최상단의 `ShareStackMac.app`에 반영합니다. 실행 중인 앱을 유지하면서 작업 폴더의 앱만 갱신하려면 `./script/build_and_run.sh --build-only`를 사용합니다. 디버거가 필요한 경우 `./script/build_and_run.sh --debug`로 Debug 빌드를 사용합니다. Xcode에서는 `macos/ShareStackMac/ShareStackMac.xcodeproj`의 `ShareStackMac` scheme을 사용할 수 있습니다. TLS 인증서 회귀 검사는 `./script/verify_tls.sh`로 실행합니다.

키체인 접근 승인이 빌드할 때마다 반복되지 않도록 서명된 작업 폴더 앱이 있으면 빌드 스크립트가 그 앱의 인증서를 다음 빌드에 재사용합니다. 해당 인증서의 개인키가 키체인에 있어야 하며, 서명에 실패하면 기존 앱을 교체하지 않습니다. 최초 로컬 서명은 `SHARESTACK_CODE_SIGN_IDENTITY`에 기존 코드 서명 인증서 이름 또는 SHA-1을 지정합니다. Apple 개발자 프로비저닝을 사용할 때는 `SHARESTACK_DEVELOPMENT_TEAM`도 지정합니다. 인증서가 없는 초기 빌드는 임시 서명 경고를 표시합니다.

임시 서명에서 인증서 서명으로 처음 바꿀 때 기존 키체인 항목에 대한 승인이 한 번 더 필요할 수 있습니다. 이때 macOS 확인 창에서 해당 Share Stack 앱에 **항상 허용**을 선택해야 다음 실행에도 승인이 유지됩니다. 키체인 잠금 상태나 사용자 접근 정책에 따른 인증까지 생략하지는 않습니다.

1. Mac과 Galaxy를 같은 Wi-Fi에 연결하거나 두 기기에서 Tailscale을 켭니다.
2. Mac의 Share Stack 메뉴에서 **QR** 탭을 열고 **Wi-Fi** 또는 **Tailscale**을 선택한 뒤 QR을 스캔합니다. Tailscale은 두 기기를 같은 Tailscale 네트워크에 연결하면 서로 다른 Wi-Fi나 모바일 데이터에서도 사용할 수 있습니다. Tailscale 주소가 표시되지 않으면 Mac에서 Tailscale을 연결하고 **새로고침**을 누릅니다. Galaxy의 **Mac 연결** 화면에서 **같은 Wi-Fi에서 Mac 검색**으로도 로컬 주소를 찾을 수 있습니다. 최초 연결에는 QR의 짝 토큰과 TLS 인증서 지문이 필요합니다. 수동 입력 값은 **연결 정보** 탭에서 연결 경로를 선택해 복사합니다.
3. Galaxy Share Stack 상단 컴퓨터 버튼에서 **선택 보내기** 또는 **받기**를 누릅니다.

전송 서버는 포트 `8765`에서 Bonjour 서비스 `_sharestack._tcp`를 광고하고, 루프백·로컬 사설 IPv4·Tailscale IPv4 연결을 받습니다. TLS 인증서 지문과 짝 토큰을 함께 확인합니다. 파일은 8 MiB 조각으로 전송하며 최대 크기는 20 GiB입니다. Mac 업로드 조각과 Galaxy 다운로드 조각은 디스크에 저장되므로 앱이나 연결이 중단돼도 다시 연결하면 마지막 위치부터 계속됩니다. 최종 파일은 SHA-256을 검증한 뒤 보관함에 기록합니다.

메뉴 앱에서 파일을 선택하거나 클립보드 텍스트를 직접 추가하면 Galaxy 전송 대기열에 들어갑니다.

### Galaxy에서 Mac 파일 받기

연결된 Mac이 있으면 휴대폰 Share Stack을 열 때 수신 대기 파일을 한 번 자동으로 확인해 보관함에 받습니다. 앱이 강제 종료된 동안 보낸 파일도 Mac 보관함에 남아 있으면 다음 실행 때 받을 수 있습니다. **Mac 연동 → 맥 대기 파일**의 **선택 수신** 또는 **전체 수신**도 사용할 수 있습니다. **자동 수신**은 기본적으로 꺼져 있으며, 켜면 15초 간격으로 Mac 대기열을 확인해 휴대폰 보관함에 받습니다. 알림에서 진행 상황을 확인하거나 중지할 수 있습니다. 자동 수신을 꺼도 수동 수신은 사용할 수 있습니다.

APK뿐 아니라 문서·사진·영상·압축파일 등 모든 파일 형식을 같은 방식으로 송수신하며 이름과 MIME 형식을 유지합니다. APK를 받아도 자동 설치하지 않습니다. 자동 수신은 알림 권한과 연결된 Mac이 필요하며 Wi-Fi 또는 Tailscale 연결을 사용합니다. 앱 강제 종료 후에는 다시 열어야 자동 수신이 재개됩니다. Android의 배터리·네트워크 제한에 따라 확인이 지연될 수 있습니다.

Codex·ChatGPT에서 LinkDeck의 텍스트 파일 전송 도구로 만든 파일도 휴대폰 수신 대기에 자동 등록됩니다. 휴대폰 수신 완료나 송신 취소는 Mac 보관함의 원본을 지우지 않습니다. 수신 완료를 기록하므로 앱을 다시 열어도 같은 항목을 반복해서 받지 않으며, 실제 파일을 Mac에서 삭제하면 더 이상 수신 대기에 표시하지 않습니다. 기존 AI 생성 전용 항목도 보관함에 남아 있으면 한 번 수신할 수 있습니다. 휴대폰에서 Mac으로 보낸 원본과 연결된 AI용 내부 사본은 다시 휴대폰으로 보내지 않습니다.

### 휴대폰에서 AI 읽기 허용

휴대폰 보관함에서 파일명 옆 **AI 허용**을 체크하면 0.7초 취소 유예 뒤 연결된 Mac으로 자동 전송합니다. Mac의 전체 수신·SHA-256 검증과 파일별 권한 반영을 확인한 뒤 **AI 읽기 준비 완료**로 표시합니다. 전송 대기·전송 중·실패 상태와 항목 배경의 준비 진행을 확인할 수 있습니다. 준비 중 다시 체크를 해제하면 취소합니다.

해제하면 원본을 남기고 Mac의 읽기 권한도 해제합니다. 연결이 끊겼으면 **해제 동기화 대기** 또는 실패로 표시하며 Mac 확인 전에는 해제 완료로 표시하지 않습니다. 대기 중인 최신 선택은 저장되며 기존 Mac 연결 서비스가 15초 간격으로 재시도합니다. 앱 강제 종료나 알림의 중지 이후에는 앱을 다시 열면 대기 작업이 재개됩니다. 연결 대상 Mac의 인증 지문별로 기록을 구분합니다.

양쪽 앱을 갱신하고 기존 QR 짝 연결을 설정해야 합니다. ChatGPT·Codex 대화에서는 해당 Mac의 LinkDeck 도구를 사용합니다. 본문 읽기는 기존 UTF-8 텍스트 범위이며 PDF·이미지 내용 추출은 포함하지 않습니다. 이미 AI에게 전달된 내용은 해제로 회수되지 않습니다.

### Mac 수신 방식과 보관함

메뉴 상단의 **설정**에서 수신 방식과 저장 폴더를 선택합니다. 기본 저장 폴더는 `~/Downloads/Share Stack`이며 기본 수신 방식은 **보관함에서 확인 후 저장**입니다.

메뉴바 아이콘을 누르면 항상 **보관함** 탭이 먼저 열립니다. 수신 대기·저장 완료·AI에서 받은 파일을 한 목록에 표시합니다. AI용 내부 사본은 원본 항목에 연결해 중복 표시하지 않습니다. 메뉴바 배지는 이 통합 목록의 개수이며, 100개 이상은 `99+`로 표시합니다.

각 파일의 **AI 읽기 허용**은 기본 해제입니다. 이전 AI Exchange 파일도 파일 자체는 보존하면서 해제 상태로 표시합니다. 체크하면 0.7초 취소 유예와 실제 파일 복사·SHA-256 검증 진행 표시가 시작되고, 완료한 뒤에만 AI의 목록·정보·내용 조회에 공개됩니다. 준비 중 다시 체크를 해제하면 취소됩니다. 허용 해제는 즉시 이후 접근을 차단하며 원본 파일을 삭제하지 않습니다. 같은 항목을 다시 허용하면 기존 검증용 사본을 재사용합니다. 전체 AI 읽기를 일시 중지하려면 **설정 → AI 읽기 사용**을 끕니다. 이미 AI에게 전달된 내용은 체크 해제로 회수할 수 없습니다.

- **보관함에서 확인 후 저장**: 받은 파일을 앱 전용 임시 보관 폴더 `~/Library/Application Support/ShareStackMac/inbox-temporary`에 둡니다. 메뉴의 **보관함**에서 **수신**을 누르면 지정 폴더로 이동하고, **취소**를 누르면 임시 파일과 대기 항목을 삭제합니다. 앱을 재실행해도 선택하지 않은 파일은 유지됩니다. 기존 버전에서 받은 파일도 보관함에서 처리할 수 있습니다.
- **지정 폴더에 자동 저장**: 전송과 SHA-256 검증이 끝나면 지정 폴더에 바로 저장합니다. 저장 폴더 접근 실패 등으로 저장하지 못한 파일은 보관함에 남고 오류가 표시됩니다.

동일한 이름의 파일은 덮어쓰지 않고 번호를 붙입니다. 설정 변경은 이후 도착하는 파일부터 적용하며 이미 보관함에 있는 파일은 직접 수신하거나 취소합니다. 보관함에는 파일마다 **수신**·**취소** 버튼이 있고 **전체 수신**으로 현재 대기 중인 모든 파일을 저장할 수도 있습니다. 일부 파일이 실패해도 나머지를 계속 저장하며 실패한 파일은 보관함에 남습니다. 보관함은 페이지당 여섯 건을 표시하고 이전·다음 버튼과 스크롤로 확인합니다.

앱 데이터는 `~/Library/Application Support/ShareStackMac`에 저장하고, 짝 토큰과 TLS 파일 암호는 macOS Keychain에 보관합니다. 이전 인증서 형식은 원본 파일과 개인키를 보존하며 변환하고 인증서를 다시 발급하므로, 기존 연결이 있었다면 QR을 다시 스캔해야 합니다. 로컬 네트워크 검색은 Android의 NSD/Bonjour를 사용합니다. ([Android NSD API](https://developer.android.com/reference/android/net/nsd/NsdManager))

## API

외부 프로그램용 맥 API는 [API 사용 문서](docs/api.md)와 [OpenAPI 명세](docs/openapi.yaml)를 참고하세요. 보관함 조회·개별/전체 수신·취소·상태·이벤트 조회와 휴대전화 송신 대기열 추가를 지원합니다. 완료 작업 상태는 메모리에 10분 동안 최대 20개 보관하며 앱 재시작 시 사라집니다. 저장된 수신 파일은 보관함에서 확인할 수 있습니다. 실제 저장 파일은 지정 폴더에 유지하며, AI 읽기는 항목별 체크 여부로 제한합니다.

LinkDeck의 앱 API 연동에는 [MCP stdio 연결 문서](docs/linkdeck.md)를 참고하세요. 앱 번들에 `linkdeck.json`이 포함되며 같은 실행 파일의 `--mcp` 모드가 실제 GUI와 통신합니다. 파일 작업은 작업 ID를 반환하고 진행 상태·결과·취소를 별도 도구로 제공합니다.

## 폴더 작업공간

Mac 설정의 **폴더 작업공간**에서 폴더를 비공개 격리 복사본으로 등록합니다. AI에서 `list_workspaces`를 호출한 뒤, 설정에서 해당 연결 ID와 읽기 전용/격리 편집 모드를 직접 승인합니다. 파일 읽기와 수정은 승인된 복사본에만 적용됩니다. 원본 반영은 지원하지 않습니다. 세션 승인·제한·patch 형식은 [MCP 연결 문서](docs/linkdeck.md#폴더-작업공간-m1m3)를 참고하세요.

## 안드로이드 제약

- 안드로이드 보안 정책 때문에 일반 앱이 모든 클립보드 복사를 백그라운드에서 계속 감시할 수는 없습니다. 텍스트를 스택에 추가하려면 다른 앱의 공유 메뉴에서 Share Stack을 선택해야 합니다.
- 여러 파일을 받을 수 있는지는 대상 앱의 구현에 따라 달라집니다. 일부 앱은 하나의 파일만 받거나 혼합 파일 형식을 거부할 수 있습니다.
- 이 경우 ZIP 공유를 사용하거나 텍스트를 별도로 붙여넣는 방식이 가장 안정적입니다.
